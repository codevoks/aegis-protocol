# ADR-0011 — `@solana/kit` as the TypeScript client stack

**Status:** Accepted · **Date:** 2026-09-04 · **Phase:** 0

## Context

Research (`ecosystem-research.md` §7) confirmed that **`@solana/kit` v8.2.0** is the current
recommended Solana TypeScript SDK, that `@solana/web3.js` is explicitly legacy, and that Anchor 1.0
renamed its TypeScript package from `@coral-xyz/anchor` to **`@anchor-lang/core`**.

Both renames are recent enough that most examples, tutorials, and model training data reference the
old names.

## Decision

- **`@solana/kit` v8.x** for RPC, codecs, transaction construction, and signing.
- **`@anchor-lang/core`** for IDL types and Anchor-specific helpers.
- `@aegis/sdk` uses Kit **directly**, not through a wrapper.
- The Next.js app consumes `@aegis/sdk`.

## Alternatives considered

**`@solana/web3.js` v1.** Rejected: legacy, larger bundles, weaker types, and it would signal
unfamiliarity with the current ecosystem.

**`gill` or `kite`** (ergonomic wrappers over Kit). Rejected for the SDK: they would sit between Aegis
and the primitives, adding a dependency and obscuring what the code actually does. Permitted in the
app layer if a specific need arises — the SDK is where the first-party knowledge should be visible.

**A Rust client instead of TypeScript.** Rejected: the UI needs TypeScript, and a second client
language would double maintenance for no gain.

## Consequences

**Positive**
- Modern, modular, tree-shakeable, strongly typed; smaller bundles.
- Matches what a current Solana team would actually use.
- Kit's codecs align well with hand-written account decoders where codegen is insufficient.

**Negative**
- Kit's API differs substantially from web3.js v1, so most examples online do not apply. Mitigated by
  the trap table in `CLAUDE.md`.
- Kit and Anchor 1.x are both recent; some integration friction is likely. Phase 9 must verify against
  installed versions rather than documentation.

**Requirements this imposes**
- `sdk/ts/src/math.ts` re-implements `aegis-math`, and re-implementations drift. The **only** accepted
  defense: shared JSON test vectors generated by the Rust tests and consumed by the TS tests, with CI
  failing on staleness (`I-SDK-01`). No hand-maintained expected values.
- `I-TX-01`: every instruction's realistic transaction must fit a **legacy 1232-byte** transaction
  without an address lookup table. Designing to the older limit means Aegis works everywhere, and
  SIMD-0296's 4096 bytes becomes headroom rather than a dependency (RV-7).
- No hardcoded RPC endpoints; local Surfpool is the default (ADR-0010).
- The Hermes client is behind an interface with an offline fixture implementation, so the app and bot
  run fully locally.
