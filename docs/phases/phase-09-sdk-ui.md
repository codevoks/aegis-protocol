## Scope

2. `sdk/ts/` — `@aegis/sdk` built on **`@solana/kit` v8.x** and **`@anchor-lang/core`** (not

## Explicit NON-scope

## Concepts demonstrated
Modern Solana TypeScript client architecture (`@solana/kit`, tree-shakeable, typed) · IDL codegen ·
PDA derivation mirroring on-chain seeds · transaction construction and size budgeting · cross-language
numeric consistency · frontend integration with a local validator.

## Critical requirement — cross-language math

`math.ts` re-implements `aegis-math`, and re-implementations drift. The **only** acceptable defense:

1. Rust tests emit `tests/vectors/*.json` with inputs and expected outputs for every formula.
2. TS tests consume the same file and assert identical results.
3. CI fails if the vectors are stale relative to the Rust implementation (`I-SDK-01`).

Do not hand-maintain a second set of expected values.

## Security notes
- The SDK never handles private keys beyond signing with a user-provided signer.
- No hardcoded RPC endpoints; local Surfpool is the default.
- No API keys in the repository; the Hermes client takes an injectable endpoint and has an offline
  fixture implementation.
- The UI must display the market's `ack_freeze_authority` flag and its oracle staleness/confidence
  parameters — these are user-facing risks and hiding them would contradict the product thesis.

## Tests
`I-TX-01` (**every instruction's realistic transaction fits 1232 bytes without an ALT**) ·
`I-SDK-01` (cross-language vectors) · `I-SDK-02` (build → sign → send → confirm → decode for every
instruction against Surfpool) · `I-SDK-03` (PDA derivations match on-chain exactly) ·
`I-UI-01` (full user flow: init, deposit, borrow, repay, withdraw).

`I-TX-01` is not a formality — `liquidate` has 14 accounts and this is the phase where an
account-count problem would first become visible.

## Demo
The complete user journey in the browser against local Surfpool: connect a local wallet, view markets,
deposit collateral, borrow, watch the health factor update, observe interest accrue over warped time,
repay, withdraw. Then a scripted price drop and a liquidation shown from the liquidator's side.
