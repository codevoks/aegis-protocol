# `@aegis/sdk`

Phase 9 TypeScript SDK for Aegis Protocol (`docs/phases/phase-09-sdk-ui.md`). Typed IDL codegen,
PDA/account/read helpers, client-side math (bigint, exact), an oracle client abstraction, and
transaction builders for every user-facing instruction.

## Stack

- **`@solana/kit` v8.x** — RPC, transaction construction, signing.
- **`@anchor-lang/core`** — IDL types and the Borsh coder.
- **Never** `@coral-xyz/anchor` or `@solana/web3.js` directly. See "No legacy dependencies" below.

## Layout

```
src/
  generated/       codegen output (idl.json, idl.ts, types.ts, accounts.ts, instructions.ts,
                    events.ts, errors.ts) -- do not edit by hand, see "Codegen" below
  anchorCoder.ts    the one shared BorshCoder instance + BN/pubkey encoding shims
  borshValues.ts    generic camelCase-typed-value <-> coder-wire-shape conversion, driven by the
                    generated FieldSpec[] schemas
  definedTypeRegistry.ts   resolves a {defined: {name}} field to its own FieldSpec[]
  ixEngine.ts       the one generic instruction-assembly function every generated builder calls
  pda.ts            canonical PDA derivation (mirrors account-model.md exactly)
  accounts.ts       typed account decoders + fetch helpers, with owner/discriminator checks
  math.ts           TS port of crates/aegis-math -- bigint, validated against tests/vectors/*.json
  read.ts           read models: MarketView, PositionView, accrue_view, APY/HF/LTV/liq-price
  oracle.ts         PriceSource-style abstraction: HermesOracleClient + offline FixtureOracleClient
  ix.ts             ergonomic transaction builders + init-bundling (re-exports generated builders)
  tx.ts             build -> sign -> send -> confirm -> decode, with a confirmation-stage callback
  errors.ts         Aegis program error decoding (from the generated error table)
  events.ts         Aegis event decoding from transaction logs
  config.ts         RPC/program-id config; local Surfpool is the only default
test/
  vectors.test.ts   I-SDK-01: math.ts vs. the real Rust aegis-math output
  pda.test.ts       I-SDK-03: pda.ts vs. real on-chain PDA derivation
  tx-size.test.ts   I-TX-01 / INV-RES-06: every instruction's realistic transaction <= 1232 bytes
  e2e.test.ts       I-SDK-02: build/sign/send/confirm/decode against a real local Surfpool
```

## Codegen

`sdk/ts/src/generated/` is derived from the current Anchor-build IDL (`target/idl/aegis.json`, the
Program Metadata layout Anchor 1.x produces) -- never hand-typed. Regenerate after any on-chain
change:

```bash
anchor build            # from the repo root -- refreshes target/idl/aegis.json
npm run codegen         # from sdk/ts/ -- rewrites src/generated/*
```

`npm run codegen:check` (or `make codegen-check` from the repo root) regenerates into a scratch
directory and diffs it against the committed one, failing if they differ -- this is how CI (and a
reviewer) catches a stale generated client without trusting anyone to remember to run `codegen`.
It never rewrites the committed files itself.

Discriminators, account/instruction/event layouts, and error codes are all derived from the IDL's
own metadata (`FieldSpec[]` schemas + the IDL's embedded discriminator bytes) -- nothing is
hand-duplicated from `programs/aegis/src`.

## Cross-language math (I-SDK-01)

`math.ts` re-implements `crates/aegis-math` in `bigint`. Rust remains the sole source of truth:

```bash
make vectors          # regenerate tests/vectors/*.json from the real aegis-math implementation
make vectors-check    # CI guard: fails if the committed vectors are stale relative to aegis-math
npm test              # (from sdk/ts/) runs vectors.test.ts against the committed vectors, plus
                       # pda.test.ts and tx-size.test.ts
```

No expected value in `test/vectors.test.ts` is hand-typed; every assertion compares against a
number the real Rust code produced. `vectors.test.ts` and `check-vectors.sh` are separate concerns
on purpose: the former proves the TS port agrees with whatever vectors are committed, the latter
proves the committed vectors are not stale relative to the current Rust implementation.

## PDA parity (I-SDK-03)

`test/pda.test.ts` asserts `pda.ts`'s derivation against `tests/vectors/pdas.json`, generated by
calling the same `Pubkey::find_program_address`-based helpers every Rust test in this repository
uses (`crates/aegis-test-kit/src/market.rs`). Covers multiple pubkeys, multiple `config_id` values
(including ones chosen specifically to catch a `u16` endian mistake), user `Position`, fee
`Position`, and both vaults.

## Transaction size (I-TX-01 / INV-RES-06)

`test/tx-size.test.ts` builds a REAL signed transaction (real generated Ed25519 signer, a compute
budget instruction, a real blockhash-shaped lifetime, `@solana/kit`'s own message compiler) for
every user-facing instruction -- including `liquidate` both without and with a realistic callback
account surface -- and asserts the serialized byte count is `<= 1232` (the classic legacy limit,
never the newer 4096-byte SIMD-0296 ceiling; see `docs/ecosystem-research.md` §17 for why). No
address lookup table is used or required.

## End-to-end (I-SDK-02)

`test/e2e.test.ts` runs the full lifecycle (init protocol, create market, init position + supply,
init position + deposit + borrow, accrue interest, repay, withdraw collateral, close position,
lender withdraw, and a scripted-price-drop liquidation) against a real local, **offline** Surfpool
validator that the test starts and deploys `aegis.so` to itself. Run with:

```bash
make build          # from the repo root -- produces target/deploy/aegis.so + target/idl/aegis.json
make sdk-test-e2e   # from the repo root, or `npm run test:e2e` from sdk/ts/
```

No external RPC, no devnet, no Hermes, no paid service.

## No legacy dependencies

This package's own code never imports `@coral-xyz/anchor` or `@solana/web3.js`. `@anchor-lang/core`
(the Anchor-1.x-approved dependency, ADR-0011) has its OWN unavoidable transitive dependency on
`@solana/web3.js` internally (its Borsh coder still produces/consumes legacy `PublicKey`/`BN`-shaped
values -- see `anchorCoder.ts`'s doc comment) -- the identical, pre-existing situation
`bots/liquidator/` (Phase 8) already has. Verify:

```bash
grep -rn "@coral-xyz/anchor" src/ test/    # no matches
grep -rn "@solana/web3\.js" src/ test/     # no matches outside comments explaining this section
npm ls @solana/web3.js                    # shows only the @anchor-lang/core -> @solana/web3.js path
```

## Security notes

- No private key handling beyond signing with a caller-supplied `TransactionSigner`/`KeyPairSigner`
  (`ix.ts`/`tx.ts` never construct, store, or persist one).
- No hardcoded RPC endpoint; `config.ts`'s only default is local Surfpool.
- No Hermes endpoint or API key required; `oracle.ts`'s `FixtureOracleClient` is fully offline.
- Every token amount, share count, price, and rate is `bigint` end to end; `Number` appears only in
  already-formatted, UI-only display conversions (`read.ts`'s `ratePerSecondToApyPercent`,
  `app/src/lib/format.ts`), never fed back into a builder.
